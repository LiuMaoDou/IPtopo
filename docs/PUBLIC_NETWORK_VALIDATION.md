# 公开网络数据自验证

验证日期：2026-10-28。数据与脚本见 [公开样本目录](../samples/public-network/README.md)、[离线验证脚本](../scripts/validate_public_network.py)、[回归测试](../backend/tests/test_public_network.py)。

## 已采集与验证

四家厂商官方文档共 38 份配置、LSDB 和辅助输出，逐文件带 URL、提取说明、SHA-256 和完整性标记。验证脚本 123 项通过，其中 38 项是文件完整性检查、85 项是功能与边界检查。17 份包含地址的配置与来源值逐条一致；3 份 Nokia 协议/策略片段没有完整接口信息，不计作完整配置成功。

Cisco 官方案例的同一 Area 0 两条 LSDB 与发布的路由表对照，两个方向的目的网段总开销都为 74，与独立参考读取器和原生 Cisco 产品适配器的 SPF 结果均一致；两个读取入口分别验收，参考读取函数仍独立放在脚本中。

## 发现与修复

| 外部样本暴露的问题 | 修复与验收 |
| --- | --- |
| Huawei Router LSA 的 `* Link ID` 未被识别 | 支持星号标记并保留行级证据；原始故障样例另外存在计数不一致，继续保守拒绝 |
| Huawei OSPF 摘要表为 Age / Len / Sequence，原实现漏掉 Len | 正确读取规范摘要列；`192.168.1.1` 的 Age=98、Sequence=0x8000000B，摘要不能生成连接 |
| Cisco `interface ATM1/0.20 point-to-point` 被忽略 | 接受 P2P / multipoint 声明后缀，保留接口名；官方样例的 200.0.0.2 和 200.0.0.3 正确提取 |
| 文档存在 `Interface Ethernet0` 大小写变化 | 接口声明关键字按大小写无关匹配，保留名称 |
| Nokia 文档复制的非断行空格使 token 失配 | 在配置输入清理时转换为普通空格，保持行号；官方基本配置两条地址均保留 |
| Huawei 扩展 IPv4 前缀带 R/X 属性，不能一概视作本 Level 内部前缀 | 明确标记为外部或重新发布的前缀从内部目的列表中移除；IPv6 属性不能污染上一条 IPv4 前缀 |
| 部分详细 LSP 未重复 SOURCE 行 | 在存在 NLPID / 已解析 reachability 时识别为详细记录；摘要仍保持非详细 |

Huawei 故障文档的 `Link count=3` 对应 4 条正文链接；该原文保持不变，验证期望是数据不足，而不是擅改计数让计算通过。其他文档片段缺少反向记录、对端 Router LSA 或 LSP，保留缺失诊断。不同文档/采集视角没有混合成一个网络。

## 结论范围

- 已验证：公开格式兼容性、配置地址与同网段推断、四厂商原生 LSDB 字段/诊断、两个公布路由的独立参考和产品 SPF 度量、异厂商输出不会被误当成有效华为 LSDB。
- ECMP 的 50% / 25% / 25% 等分担仍由合成回归覆盖；本轮公开资料没有提供可对照实测流量的完整同批次 ECMP/FIB 采集，未把理论比例声称为实测分担。
- 当前产品支持四厂商原生配置与 OSPFv2/IS-IS LSDB。共用 RoutingFacts / Batch / SPF；新增适配器不翻译成华为 CLI。范围为单 Area / Level Standard IPv4，复杂策略与扩展语义仍须单独适配。
- 数据为厂商文档实验/示例，包含旧 IOS 版本以及 Nokia 多种 CLI，不等于对全部平台版本或生产网络的认证。
